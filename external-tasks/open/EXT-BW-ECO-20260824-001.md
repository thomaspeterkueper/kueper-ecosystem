# EXT-BW-ECO-20260824-001 — buecherwelten im KUEPER-Ökosystem registrieren

## Anlass

Das private Repository `thomaspeterkueper/buecherwelten` ist die Authoring- und Entwicklungsschicht für Buchprojekte und werkbezogene Medien. Der ursprüngliche Auftrag liegt im Quellrepository unter `external-tasks/open/EXT-BW-ECO-20260824-001.md` und richtet sich ausdrücklich an ECO.

## Gewünschte Änderung

- `buecherwelten` in `registry/projects.json` registrieren.
- einen verbindlichen Ökosystem-Code bestätigen bzw. vergeben; vorgeschlagen ist `BW`.
- die Source-of-Truth-Abgrenzung dokumentieren:
  - BW = private Arbeitsstände/Authoring-Zustände,
  - NXU = bestätigte universumsweite Primärdaten der NOXIA-Kontinuität,
  - OTA = ausschließlich kanonische OTA-*-Dokumente,
  - KG = projektübergreifende IDs, Mappings und semantische Relationen.
- Collector/Dashboard und External-Task-Governance auf das Repository erweitern.

## Begründung

Projekt-Registry, Rollenmodell, Ökosystem-Codes, Source-of-Truth-Abgrenzung,
Collector/Dashboard und External-Task-Governance liegen vollständig in der
Zuständigkeit von `kueper-ecosystem` (ECO) als Normierungsstelle. Die
Registrierung eines neuen Repositorys ist damit ein ECO-eigener Auftrag.

## Betroffene Repositories

- `kueper-ecosystem` (Registry, Schema, Dokumentation, Collector/Dashboard, Governance)
- `buecherwelten` (wird registriert; keine Änderungen am Repository selbst erforderlich)
- als Referenz der Abgrenzung: `noxia-universe` (NXU), `overtime-archive.org` (OTA), `kueper-knowledge-graph` (KG)

## Erwartetes Ergebnis

- `buecherwelten` ist in `registry/projects.json` mit verbindlichem Code `BW` registriert.
- Die Source-of-Truth-Abgrenzung BW/NXU/OTA/KG ist in `docs/source-of-truth.md` dokumentiert.
- Collector/Dashboard und External-Task-Governance (Schema, Linter, Loop-Tooling) kennen das Repository.
- Für private Repositories ist festgelegt, welche Metadaten öffentlich bzw. nur intern verarbeitet werden.

## Stale-Prüfung 2026-08-29

Der Auftrag ist fachlich sinnvoll, aber aktuell nicht ohne Governance-/Schemaentscheidung sicher umsetzbar:

1. `schemas/project-registry.schema.json` besitzt derzeit **kein Feld für einen Ökosystem-Code**. Der vorgeschlagene Code `BW` kann daher nicht einfach kanonisch in der Registry hinterlegt werden, ohne festzulegen, wo solche Codes künftig verbindlich geführt werden.
2. Die erlaubten Registry-Rollen enthalten **keine Authoring-Rolle**. `buecherwelten` ist laut Auftrag weder Anwendung, Archiv, Wissensplattform, Website noch Infrastruktur im bestehenden Sinn. Eine vorhandene Rolle ersatzweise zu wählen oder das Schema um `authoring` zu erweitern wäre eine Architektur-/Governanceentscheidung.
3. Das Repository ist privat und kann private Autorendaten enthalten. Die Aufnahme in Collector/Dashboard muss deshalb explizit klären, welche Metadaten öffentlich bzw. nur intern verarbeitet werden dürfen.

## Konkreter nächster Schritt

Governance-Entscheidung zu zwei Punkten festhalten:

- **Code-System:** `BW` bestätigen und festlegen, in welchem bestehenden oder neuen Registry-Feld Projektcodes verbindlich gespeichert werden.
- **Rolle:** entweder eine vorhandene Rolle ausdrücklich für private Authoring-Repositories bestimmen oder die Registry um eine Rolle wie `authoring` erweitern.

Nach dieser Entscheidung ist die technische Umsetzung lokal im `kueper-ecosystem`-Repository eindeutig: Registry, Source-of-Truth-Dokumentation, Collector/Dashboard-Konfiguration und External-Task-Governance ergänzen. Bis dahin bleibt der Auftrag offen; keine Registrierung wird geraten.

## Umsetzungsvorschlag (2026-08-29)

PR #47 legt die technische Umsetzung der drei Blocker als Vorschlag vor
(siehe `decisions/ECO-ARC-0031-2026-DE.md`; beide Entscheidungen ECO-ARC-0030
und ECO-ARC-0031 bleiben bis zur Owner-Abnahme `proposed`):

1. **Code-System:** `BW` wird als Code vorgeschlagen. Ökosystem-Codes sollen
   künftig kanonisch im Registry-Feld `code` geführt werden (Schema-Revision
   1.1.0); alle bestehenden Codes wurden in das Feld überführt.
2. **Rolle:** Die Registry-Rolle `authoring` wird vorgeschlagen; `buecherwelten`
   ist damit registriert (`role: authoring`, `code: BW`, `sensitivity:
   private-manuscript-source` mit deny-by-default für Kanonisierung/Export).
3. **Private Metadaten:** Collector und Dashboard verarbeiten für private
   Repositories ausschließlich operative Metadaten (Erreichbarkeit, Branch,
   letzter Push, PR-Anzahl, Pfadprüfungen, Task-Metadaten), niemals Inhalte;
   private Projekte werden im Dashboard als `privat` markiert.

Zusätzlich vorgeschlagen:

- Registry-Eintrag `buecherwelten` in `registry/projects.json`.
- Source-of-Truth-Abgrenzung BW/NXU/OTA/KG in `docs/source-of-truth.md`
  (Abschnitt 3a), ergänzt in `docs/repository-roles.md`, `docs/system-map.md`,
  `README.md` und `registry/README.md`.
- External-Task-Governance um `BW` erweitert: `schemas/external-task.schema.json`,
  `tools/lint-external-tasks/lint.py`, `tools/loop/ingest_external_tasks.py`,
  `tools/loop/orchestrate.py`, `tools/loop/reevaluate_parked.py`; Code-Tabelle
  in ECO-ARC-0006 ergänzt.
- Routing von Outbox-Envelopes an `BW` bleibt bis zur separaten
  Vertraulichkeits-/Provenienz-Erweiterung deaktiviert (ECO-ARC-0030/0031).
