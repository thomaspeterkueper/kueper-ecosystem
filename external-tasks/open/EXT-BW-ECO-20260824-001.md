# EXT-BW-ECO-20260824-001 — buecherwelten im KUEPER-Ökosystem registrieren

## Anlass

Das private Repository `thomaspeterkueper/buecherwelten` ist die Authoring- und Entwicklungsschicht für Buchprojekte und werkbezogene Medien. Der ursprüngliche Auftrag liegt im Quellrepository unter `external-tasks/open/EXT-BW-ECO-20260824-001.md` und richtet sich ausdrücklich an ECO.

## Gewünschte Änderung

- `buecherwelten` in `registry/projects.json` registrieren.
- einen verbindlichen Ökosystem-Code bestätigen bzw. vergeben; vorgeschlagen ist `BW`.
- die Source-of-Truth-Abgrenzung dokumentieren:
  - BW = private Arbeitsstände/Authoring-Zustände,
  - NXU = bestätigte universumsweite Primärdaten der NOXIA-Kontinuität,
  - OTA = ausschließlich kanonische OTA-*-Dokumente,
  - KG = projektübergreifende IDs, Mappings und semantische Relationen.
- Collector/Dashboard und External-Task-Governance auf das Repository erweitern.

## Stale-Prüfung 2026-08-29

Der Auftrag ist fachlich sinnvoll, aber aktuell nicht ohne Governance-/Schemaentscheidung sicher umsetzbar:

1. `schemas/project-registry.schema.json` besitzt derzeit **kein Feld für einen Ökosystem-Code**. Der vorgeschlagene Code `BW` kann daher nicht einfach kanonisch in der Registry hinterlegt werden, ohne festzulegen, wo solche Codes künftig verbindlich geführt werden.
2. Die erlaubten Registry-Rollen enthalten **keine Authoring-Rolle**. `buecherwelten` ist laut Auftrag weder Anwendung, Archiv, Wissensplattform, Website noch Infrastruktur im bestehenden Sinn. Eine vorhandene Rolle ersatzweise zu wählen oder das Schema um `authoring` zu erweitern wäre eine Architektur-/Governanceentscheidung.
3. Das Repository ist privat und kann private Autorendaten enthalten. Die Aufnahme in Collector/Dashboard muss deshalb explizit klären, welche Metadaten öffentlich bzw. nur intern verarbeitet werden dürfen.

## Konkreter nächster Schritt

Governance-Entscheidung zu zwei Punkten festhalten:

- **Code-System:** `BW` bestätigen und festlegen, in welchem bestehenden oder neuen Registry-Feld Projektcodes verbindlich gespeichert werden.
- **Rolle:** entweder eine vorhandene Rolle ausdrücklich für private Authoring-Repositories bestimmen oder die Registry um eine Rolle wie `authoring` erweitern.

Nach dieser Entscheidung ist die technische Umsetzung lokal im `kueper-ecosystem`-Repository eindeutig: Registry, Source-of-Truth-Dokumentation, Collector/Dashboard-Konfiguration und External-Task-Governance ergänzen. Bis dahin bleibt der Auftrag offen; keine Registrierung wird geraten.
