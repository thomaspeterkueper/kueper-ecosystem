# ANLEITUNG: Wissen aus alten Chats ins KUEPER-Ecosystem transferieren

**Zweck:** Diese Anleitung hilft dir, alte Claude-Chats systematisch aufzuräumen,
ihr Wissen ins GitHub-Ecosystem zu überführen und die Chats danach zu löschen.

---

## 1. Was du in jeden alten Chat kopierst

Füge diesen Text am Anfang des alten Chats ein:

---

**[AN CLAUDE IN DIESEM CHAT]**

Ich möchte alles Wissen aus diesem Chat ins KUEPER-Ecosystem überführen,
damit ich den Chat danach löschen kann. Bitte hilf mir dabei strukturiert.

**Das Ecosystem:**
- GitHub: https://github.com/thomaspeterkueper
- Zentrale Steuerung: `kueper-ecosystem` Repo
- Wissen wird als External Tasks in die zuständigen Repos gelegt
- Niemals direkt in fremde Repos schreiben — immer als Task

**Task-Format (Dateiname):** `EXT-{QUELLE}-{ZIEL}-{YYYYMMDD}-{NNN}.md`
**Task-Ablage:** `external-tasks/open/` im Ziel-Repo

**Bitte tu jetzt folgendes:**

1. Lies den gesamten Chat durch
2. Identifiziere alles was kanonisch, inhaltlich oder strukturell relevant ist
3. Ordne jeden Fund dem richtigen Ziel-Repo zu (Tabelle unten)
4. Erstelle Draft-Tasks — zeige sie mir zur Freigabe bevor du pushst
5. Wenn ich freigebe: push mit Token (ich gebe dir eines)
6. Dann kann ich den Chat löschen

**Was gehört NICHT ins Ecosystem:**
- Reine Brainstorms ohne Entscheidung
- Verworfene Ideen (explizit verworfen)
- Technische Debugging-Sessions ohne Ergebnis
- Smalltalk

## 3. Token sicher übergeben

Erstelle ein **fine-grained Token** mit minimalen Rechten:

1. https://github.com/settings/tokens → "Generate new token (fine-grained)"
2. Repository access: **nur die Repos die gebraucht werden**
3. Permissions: Contents → **Read and write**
4. Expiration: **1 day**
5. Token nach der Session sofort widerrufen: https://github.com/settings/tokens

**Niemals** ein Token mit Vollzugriff oder langer Laufzeit verwenden.

---

## 4. Kontrolle vor dem Löschen

Bevor du den Chat löschst, bitte Claude zu bestätigen:

- Welche Tasks wurden in welche Repos gepusht?
- Gibt es offene Punkte die noch nicht transferiert wurden?
- Gibt es Noxia-Kanon der noch in die Supabase-DB muss?

Erst wenn alles bestätigt ist: Chat löschen.

---

## 5. Supabase nachpflegen (Noxia-spezifisch)

Manche Erkenntnisse müssen auch in die Supabase-Datenbank des
`noxia-universe` Projekts. Claude schreibt dir SQL-Statements,
die du im Supabase SQL Editor ausführst.

Tabellen die oft nachgepflegt werden:
- `timeline_events` — neue Ereignisse
- `characters` — neue oder aktualisierte Charaktere
- `open_questions` — neue offene Fragen
- `physics_concepts` — neue Physik-Konzepte
- `language_phrases` — neue Mishkenaz-Phrasen

---

## 6. Checkliste pro Chat

```
□ Thema des Chats grob identifiziert (Noxia / Philosophie / Physik / etc.)
□ Chat vollständig gelesen
□ Alle relevanten Inhalte identifiziert und zugeordnet
□ Tasks formuliert und zur Freigabe gezeigt
□ Token erstellt (minimal, 1 Tag, nur nötige Repos)
□ Tasks gepusht und verifiziert
□ Token widerrufen
□ Supabase nachgepflegt (falls Noxia-Kanon)
□ Chat gelöscht
```
