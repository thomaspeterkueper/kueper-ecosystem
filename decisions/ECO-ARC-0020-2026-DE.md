# ECO-ARC-0020-2026-DE — Autonomes Routing von Folge-Requests

Status: accepted  
Datum: 2026-07-25  
Scope: systemweit  
Betroffene Repositories: alle registrierten KUEPER-Repositories

## Kontext

ECO-ARC-0019 führt den autonomen Execution Loop ein. V1 konnte einen während der Bearbeitung erkannten Cross-Repo-Bedarf nur dokumentieren. Damit blieb für die Weiterleitung weiterhin ein manueller Schritt nötig.

## Entscheidung

Projekt-Agenten dürfen konkrete, durch ihre aktuelle Arbeit verursachte Cross-Repo-Bedarfe als strukturierte JSON-Envelopes unter `.kueper/outbox/` erzeugen. Nur das `kueper-ecosystem` darf diese Envelopes in kanonische External Tasks des Ziel-Repositories übersetzen.

Das Ziel wird ausschließlich über die registrierten System-Codes bestimmt. Ein Agent darf kein anderes Repository direkt ändern.

Automatisches Routing ist begrenzt durch:

- maximale Routing-Tiefe 3;
- standardmäßig maximal 10 neue Requests pro Sweep;
- Fingerprint-Deduplizierung;
- Verbot von Source=Target;
- Pflicht zu konkretem Anlass, gewünschter Änderung und erwartetem Ergebnis;
- keine freie Ideen-/Research-Expansion in dieser Stufe.

## Begründung

Damit kann jedes Projekt seine eigenen Tasks selbständig bearbeiten und zugleich fachlich fremden Folge-Bedarf an das zuständige Projekt delegieren, ohne Source-of-Truth-Grenzen aufzuweichen. Die verzögerte Bearbeitung im nächsten Sweep verhindert rekursive Agentenketten innerhalb eines einzelnen Laufs.

## Auswirkungen

Aus `A → B → C` kann eine autonome, nachvollziehbare Task-Kette entstehen. Jeder geroutete Task enthält Parent-ID, Routing-Tiefe und einen Deduplizierungs-Fingerprint. Rückfragen bleiben weiterhin ein legitimer Stop-Zustand.

## Nicht entschieden

Freie Wissensvertiefung, automatische Web-Recherche, Canon-Conflict-Erkennung und autonome Ideenfindung werden separat geregelt.

## Folgeaufgaben

1. V2 im realen Sweep beobachten.
2. Nach stabilen Routing-Läufen Knowledge-Expansion als getrennten Loop definieren.
