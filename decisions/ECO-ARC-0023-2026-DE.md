# ECO-ARC-0023-2026-DE — Automatische Wiederaufnahme geparkter Tasks

Status: accepted  
Datum: 2026-07-26  
Scope: systemweit  
Betroffene Repositories: alle registrierten KUEPER-Repositories

## Kontext

Der erste reale V3/V4-Pilot zeigte einen fehlenden Rückkopplungsschritt: Ein Task kann korrekt geparkt werden, weil im Ziel-Repository eine interne Voraussetzung fehlt. Wenn diese Voraussetzung später erfüllt wird, würde der Task ohne erneute Prüfung dauerhaft liegen bleiben und wieder manuellen Owner-Eingriff erfordern.

## Entscheidung

Vor jedem regulären Ecosystem-Sweep werden begrenzt geparkte Tasks gegen den aktuellen Stand ihres Ziel-Repositories neu bewertet.

Der Reevaluation-Agent darf einen Task nur dann nach `external-tasks/open/` zurückführen, wenn die zuvor fehlende interne Voraussetzung inzwischen vorhanden ist. Er implementiert den Task nicht.

Bei expliziten kreativen, fachlichen oder architektonischen Owner-Entscheidungen bleibt der Task geparkt. Fehlende Evidenz gilt nicht als erfüllte Voraussetzung.

## Begrenzung

Standardmäßig werden höchstens drei geparkte Tasks pro Sweep neu bewertet. Dadurch wird verhindert, dass alte Backlogs unverhältnismäßig Agentenbudget verbrauchen.

## Begründung

Damit bleibt `parked` ein temporärer Systemzustand statt eines manuellen Endlagers. Das Ecosystem kann interne Abhängigkeiten selbst erkennen und Arbeit automatisch fortsetzen, sobald sie sinnvoll möglich ist.

## Auswirkungen

Der Ablauf erweitert sich zu:

`parked → regelmäßiger Preflight → blocker weiterhin aktiv ODER reopen → normaler Project Loop`

## Folgeaufgaben

1. Reaktivierungsqualität im Betrieb beobachten.
2. Langfristig blocker-spezifische Recheck-Intervalle einführen.
3. Owner-Entscheidungen separat von technischen/internen Blockern kennzeichnen.
