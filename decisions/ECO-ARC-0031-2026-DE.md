# ECO-ARC-0031-2026-DE — buecherwelten (BW): Registrierung, Code-Feld, Authoring-Rolle, Vertraulichkeitsmodell

Status: accepted
Datum: 2026-08-29
Scope: systemweit
Betroffene Repositories: `kueper-ecosystem`, `buecherwelten`, sowie als Referenz `noxia-universe`, `overtime-archive.org`, `kueper-knowledge-graph`

## Kontext

Der External Task `EXT-BW-ECO-20260824-001` fordert, `thomaspeterkueper/buecherwelten`
als Authoring- und Entwicklungsschicht für Buchprojekte und werkbezogene Medien im
KUEPER-Ökosystem zu registrieren. Die Stale-Prüfung (2026-08-29) hält fest, dass die
Umsetzung ohne Governance-Entscheidungen nicht sicher möglich ist:

1. Das Registry-Schema besitzt kein Feld für einen Ökosystem-Code; unklar, wo Codes
   künftig verbindlich geführt werden.
2. Die Registry-Rollen enthalten keine Authoring-Rolle.
3. Das Repository ist privat; Collector/Dashboard müssen klären, welche Metadaten
   öffentlich bzw. nur intern verarbeitet werden dürfen.

`ECO-ARC-0030` (Private Manuscript Repositories) hat die logische Repository-Klasse
`private-manuscript-source` eingeführt und die Aktivierung im Project Registry von
einer rückwärtskompatiblen Schema-Revision abhängig gemacht. Diese Entscheidung
realisiert die in ECO-ARC-0030 geforderten Voraussetzungen und setzt den Auftrag um.

## Entscheidung

### 1. Ökosystem-Code

Der Code für `buecherwelten` ist verbindlich **`BW`**.

Codes werden künftig **verbindlich im Registry-Feld `code`** geführt (nicht mehr
nur in Freitext-`notes`). Das Feld ist optional, damit bestehende Einträge gültig
bleiben; mit dieser Entscheidung werden alle bestehenden Codes in das Feld
überführt. Die Code-Tabelle in ECO-ARC-0006 bleibt die Referenzliste der
vergebenen Codes und wird um `BW` ergänzt.

### 2. Rolle

Das Registry-Schema wird um die Rolle **`authoring`** erweitert. Sie bezeichnet
private Arbeitsstände/Authoring-Zustände (Manuskripte, Szenen, Kapitelstände,
werkbezogene Medien) und ist bewusst von `archive`, `knowledge-platform` und
`website` getrennt: eine Authoring-Quelle ist keine Publikationsschicht.

### 3. Sensitivität und Berechtigungen

Das Registry-Schema erhält ein optionales Feld `sensitivity`, das für
`buecherwelten` wie folgt belegt wird (Abbildung der von ECO-ARC-0030 geforderten
Merkmale):

- `repository_class`: `private-manuscript-source`
- `ingest`: erlaubt (private Analyse)
- `canonization`: verboten (keine automatische Kanonisierung)
- `public_export`: verboten (private source -> public target ist deny-by-default)
- `derived_analysis`: erlaubt (private, nicht-kanonische Artefakte)

`buecherwelten` erhält keine `integrations`-Einträge: Beziehungen zu NXU/KG/OTA
sind Referenzrichtungen, die nur durch ausdrückliche Promotion-Entscheidungen zu
Datenflüssen werden dürfen (ECO-ARC-0030).

### 4. External-Task-Governance

Der Code `BW` wird in den kanonischen Code-Satz aufgenommen:

- `schemas/external-task.schema.json` (id-Muster, source, target, affects),
- `tools/lint-external-tasks/lint.py` (Code-Set und Muster),
- `tools/loop/ingest_external_tasks.py` (Code->Projekt-Auflösung),
- `tools/loop/orchestrate.py` (Projekt->Code-Systemkarte, Inbox-Scan),
- `tools/loop/reevaluate_parked.py` (Code-Systemkarte).

Damit ist `EXT-BW-ECO-20260824-001` als kanonischer Task mit `source: BW` gültig.
Das Routing von Outbox-Folge-Envelopes **an** `BW` bleibt deaktiviert (keine
Aufnahme in `route_followups.py`/`cleanup_outbox.py`/Worker-Ziellisten), bis die
von ECO-ARC-0030 geforderte kompatible Erweiterung für Vertraulichkeits- und
Provenienzmerkmale separat geprüft ist.

### 5. Collector und Dashboard: Metadaten-Policy für private Repositories

Collector und Dashboard verarbeiten für `buecherwelten` **ausschließlich operative
Metadaten**: Erreichbarkeit, Default Branch, letzter Push, Anzahl offener PRs
(keine Titel), Existenz von Governance-Pflichtpfaden, Dateinamen und Frontmatter
offener External Tasks, `private`-Flag. **Inhalte** (Manuskripte, Datei-Inhalte)
werden von Collector und Dashboard weder gelesen noch gespeichert.

`status/snapshot.json` enthält für private Projekte damit nur operative Metadaten
und niemals Secret-Werte. Das Dashboard ist durch Deployment Protection
zugriffsgeschützt (interne Sicht) und markiert private Projekte sichtbar als
`privat`. Für die Überwachung benötigt der read-only `GH_TOKEN` Leseberechtigung
(`Contents: read`, `Metadata: read`, `Pull requests: read`) auch für
`buecherwelten`.

### 6. Source-of-Truth-Abgrenzung

Verbindlich dokumentiert (siehe `docs/source-of-truth.md`):

| Code | Zuständigkeit |
|---|---|
| `BW` | private Arbeitsstände/Authoring-Zustände (buecherwelten) |
| `NXU` | bestätigte universumsweite Primärdaten der NOXIA-Kontinuität |
| `OTA` | ausschließlich kanonische `OTA-*`-Dokumente |
| `KG` | projektübergreifende IDs, Mappings und semantische Relationen |

## Begründung

Die drei Blocker der Stale-Prüfung sind ausschließlich ECO-eigene Governance- und
Schemathemen (Registry-Schema, Rollenmodell, Code-System, Collector-Policy). Sie
werden hier entschieden statt geparkt, weil ECO die zuständige Normierungsstelle
ist und ECO-ARC-0030 die Umsetzungsvoraussetzungen bereits benannt hat.

## Auswirkungen

- Registry-Schema-Revision 1.1.0 (rückwärtskompatibel: neue Felder optional).
- Ein neuer Registry-Eintrag (`buecherwelten`, Rolle `authoring`, Code `BW`).
- `buecherwelten` erscheint automatisch in Collector-Snapshot und Dashboard.
- `EXT-BW-ECO-20260824-001` wird als gültiger kanonischer Task lint-bar und nach
  `external-tasks/done/` überführt.

## Nicht entschieden

- Ob und wann `BW` als Routing-Ziel für Outbox-Envelopes freigeschaltet wird
  (abhängig von der separaten External-Task-Erweiterung um Vertraulichkeits-/
  Provenienzmerkmale, ECO-ARC-0030).
- Konkrete Promotion-Regeln von Authoring-Inhalten nach NXU/KG/OTA (bleiben
  Einzelentscheidungen des Owners).
- Ein kanonischer Status `blocked` im External-Task-Format (nicht Bestandteil
  dieses Auftrags).

## Folgeaufgaben

1. Registry, Schema, Dokumentation und Tooling gemäß dieser Entscheidung
   umsetzen. (erledigt, 2026-08-29)
2. Collector-Snapshot beim nächsten geplanten Lauf neu erzeugen (enthält dann
   `buecherwelten`; der GH_TOKEN muss das private Repository lesen dürfen).
